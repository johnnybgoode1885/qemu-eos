# Canon EOS 5D Mark IV 1.3.3 emulation

The experimental 5D4 model boots Canon firmware 1.3.3 into parts of its GUI.
The graphics implementation handles selected firmware commands and renders
their output; it does not emulate the Zico processor or camera sensor.
See the [changelog](../Changelog).

## Build and dependencies

Use the `qemu-eos-v4.2.1` branch. Alongside the existing QEMU build dependencies,
install FreeType and Cairo development headers/libraries and `pkg-config`.
GTK support is needed for the interactive launcher. Python 3 is needed by the
offline vector tool; it requires no third-party Python packages.

For a fresh build outside the source directory, from the repository root:

```sh
mkdir -p ../qemu-eos-build
cd ../qemu-eos-build
../qemu-eos/configure --target-list=arm-softmmu --enable-plugins --disable-docs --enable-vnc --enable-gtk --disable-vte
make -j8
```

Adapt the source-directory name in the configure command if your checkout is
named differently. If an existing configured build encounters unrelated
submodule checks during a top-level rebuild, build its target directly:

```sh
make -C build/arm-softmmu -j8 qemu-system-arm
```

That command assumes the existing build directory is `build/` inside the
repository. Do not reset unrelated submodules to bypass a build error.
The model's renderer is part of `qemu-system-arm`; the separate ML tracing
plugin is not required by this launcher.

## Inputs and firmware mapping

Supply your own flat **32 MiB `ROM1.BIN`** and **16 MiB `SFDATA.BIN`** in one
directory. Firmware, serial flash, card images, screenshots and captured
logs are not distributed with this change. Serial flash and card contents
can identify the camera or contain images; keep them private.

The ROM is mapped at FC000000 and aliased at FE000000. For a ROM resource,
the file offset is virtual address minus its FC000000 or FE000000 base.
Use the exact dump associated with the addresses you are investigating;
two files with the same name need not have identical bytes. Preserve their
hashes locally for reproducibility.

The launcher expects existing disk images at
`magiclantern/disk_images/sd.qcow2` and `cf.qcow2`. It neither creates these
images nor enables card boot flags. Use the established EOS disk-image setup
with privately supplied contents. Its `-snapshot` option sends guest writes
to temporary overlays, which are discarded when QEMU exits.

## Launcher

From the repository root:

```sh
magiclantern/run_5d4_133.sh --help
magiclantern/run_5d4_133.sh /path/to/private-dump
magiclantern/run_5d4_133.sh /path/to/private-dump/ROM1.BIN /tmp/5d4-session.log --gui
```

For an external build:

```sh
QEMU_EOS_BINARY=/path/to/qemu-eos-build/arm-softmmu/qemu-system-arm magiclantern/run_5d4_133.sh /path/to/private-dump --gui
```

The launcher stages symlinks in a temporary directory and removes them on
exit. It sets `TMPDIR=/tmp` for QEMU's disposable overlays. Headless runs stop
after 30 seconds; GUI runs continue until the window is closed. Output is
saved to `/tmp/5d4-qemu.log` unless a log path is supplied. The default log is
replaced on each run. Retain selected logs privately outside `/tmp` when
needed for research. Stop your test instance before running other tools
against the same images.

Page Up/Page Down act as the rear dial, and Space sends SET. Those inputs
were observed navigating Zone/Time difference and changing Paris to Azores.
F1 prints keyboard help in the launching terminal. Joystick mappings are
provisional. A received key log alone is not evidence that a control works;
check the settled screen after repeated inputs.

## Vector resource inspection

`tools/decode_canon_vector.py` converts a tagged ROM vector resource to an
SVG containing its geometry. Its arguments are ROM file, virtual resource
address and output SVG. Both FC and FE aliases are accepted:

```sh
python3 magiclantern/tools/decode_canon_vector.py --help
python3 magiclantern/tools/decode_canon_vector.py /path/to/private-dump/ROM1.BIN "$RESOURCE_ADDRESS" icon.svg
```

Set `RESOURCE_ADDRESS` to an address found in your own resource investigation;
there is no universal address for every firmware. The output is written on
the host and an existing output file is replaced. Input headers and lengths
are checked. The SVG uses black paths and does not reproduce the renderer's
paint colors, clipping or descriptor transforms. Exported icon geometry is
derived from your firmware; review it before distributing it.

## Implementation and verification limits

The model supplies firmware-specific RAM, RTC, IPC and peripheral responses.
The MPU fixture replays selected startup exchanges. Some packets are moved
earlier to let initialization progress, and battery identifier bytes are
synthetic zeros. It is not a complete MPU implementation or a byte-exact
record of the physical camera's state.

The graphics path supports palette C0, fill DF, mask E4, ASCII text 40,
vector objects 7B and composition 24. FreeType reads the font from the guest
ROM at runtime; no font binary is bundled. The vector renderer handles
tagged path commands, even-odd fills and paint/path references with Cairo.
Scanout is latched during composition and LCD interrupt 0x86 advances
display callbacks.

Earlier settled-screen observations showed the date dialog, text, arrows,
GPS/daylight-saving symbols and main-menu icons. Text sizing is fixed,
transforms are incomplete and menu colors are imperfect. Live View and
recording are not validated. Hardware observations must be recorded
separately from emulator behavior. Recheck visible behavior after changing
the MPU fixture or graphics path.

Detailed packet logging uses `-d io,verbose` when invoking QEMU directly;
the launcher uses `-d io`. `hw/eos/dbi/logging.c` adds traces at the 1.3.3
GUI dispatcher addresses. Logs and exported guest memory may contain private
state. If using QEMU's monitor directly, quote output filenames, for example
`pmemsave 0 0x1000000 "/tmp/guest-memory.bin"`.

## Current checks

The existing ARM system target built successfully. Synthetic tool checks
verified FC/FE alias equivalence, SVG geometry, invalid input rejection,
launcher staging and snapshot arguments. A 30-second headless run with
private local inputs hit `MaxIso != CODE8_ISO_AUTO` in
`LvCommon/LvGainController.c` in the Gmt task. It is a smoke-run limitation,
not a passing GUI or recording test. Earlier interactive observations above
have not been revalidated by that run.
The same assertion occurred with the original private fixture, so it was
not introduced by removing the battery identifier bytes. Both test instances
were stopped and the sanitized fixture was restored and rebuilt.
